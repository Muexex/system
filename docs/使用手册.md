## 1. 使用方式与角色说明

研伴答疑提供实时、按次的一对一学习答疑。学生描述一个具体问题，在线教师接受邀请后进入临时答疑室，双方交流并主动结束，学生随后填写反馈。

平台中的“教师”指成年、非在职、全日制在校大学生或研究生。注册资料由本人填写，管理员审核后启用接单权限；此审核不代表完成第三方学籍核验。

### 1.1 先确定其他电脑如何使用

| 方式 | 其他电脑需要做什么 | 数据位置 |
| --- | --- | --- |
| 在新电脑上独立安装 | 安装Git、Node.js，下载代码、初始化并启动 | 新电脑自己的数据库；初始没有原电脑的账号和记录 |
| 访问已有电脑上的网站 | 使用浏览器访问服务电脑的局域网地址 | 统一保存在服务电脑；客户端不需要安装Git和Node.js |
| 通过互联网访问 | 由维护人员配置服务器、HTTPS及访问地址，用户通过浏览器使用 | 统一保存在部署服务器 |

**如果多位用户需要互相匹配、共享同一平台，应访问同一台服务电脑或服务器。分别在两台电脑独立安装并访问各自的localhost，会得到两套独立数据库。**

GitHub保存网站代码，数据库、账号和图片不随GitHub下载。项目目前没有自动部署到公网。

### 1.2 三类用户

| 角色 | 主要操作 | 入口 |
| --- | --- | --- |
| 学生 | 注册、登录、提问、匹配、交流、反馈、查看本人历史 | `/student/login` |
| 教师 | 注册、填写资料、等待审核、上线接单、交流、查看本人历史 | `/teacher/login` |
| 管理员 | 审核与启用教师、设置科目、查看统计和运行诊断、导出汇总 | `/admin/login` |

学生、教师和管理员的登录会话独立，学生与教师的账号、密码和资料分别存储。相同账号名可以分别注册学生和教师，但必须从相应入口登录。管理员使用独立入口，没有公开注册页面或默认密码。

## 2. 安装前准备

本节仅由需要安装并运行服务的电脑执行。仅通过浏览器访问已有网站的用户，可直接阅读第7、8节。

### 2.1 安装Git

1. 从官方页面下载Git for Windows：<https://git-scm.com/downloads/win>。
2. 按安装程序指引完成安装。一般保留默认选项即可。
3. 安装完成后打开Git Bash。

Git通常安装在`C:\Program Files\Git`。GitHub是代码托管网站，不要求安装GitHub Desktop。

### 2.2 安装Node.js 22 LTS

当前项目支持22.13及以上的22.x版本，建议使用22.23.3。安装包：

<https://nodejs.org/dist/v22.23.3/node-v22.23.3-x64.msi>

1. 如电脑已有Node.js 24，先替换为22 LTS。
2. 安装时保留npm和PATH选项；“自动安装本机模块所需工具”选项可不勾选，本手册提供现成Windows驱动的安装方法。
3. 安装完成后关闭旧终端，重新打开Git Bash。

Node.js通常安装在`C:\Program Files\nodejs`。项目代码另外保存在用户目录，不放在Node.js安装目录中。

### 2.3 确认环境

在Git Bash逐条执行：

```bash
git --version
node -v
npm -v
```

三条命令应分别显示版本号；`node -v`应为`v22.x.x`。如果提示找不到命令，检查安装及PATH，再重新打开终端。

**本手册中的命令应按步骤执行。上一条成功后再继续；出现错误时先处理错误。交互式创建管理员命令应单独执行，避免后续命令被当成账号或密码输入。**

## 3. 从GitHub获取网站代码

### 3.1 首次下载

在Git Bash执行：

```bash
cd ~
git clone https://github.com/Muexex/system.git
```

下载成功后进入项目：

```bash
cd ~/system
```

在Windows中，该目录一般对应`C:\Users\当前Windows用户名\system`。终端末尾出现`~/system`，表示已进入项目目录。

如果仓库要求登录GitHub，应使用有仓库访问权限的账号完成授权。HTTPS下载不要求事先配置SSH密钥。

如果提示`system`目录已经存在，先确认该目录是否就是已有项目；已有项目的更新按第11节处理。

### 3.2 以后如何进入项目

每次新开Git Bash，先执行：

```bash
cd ~/system
```

安装、初始化、创建管理员、构建和启动命令均在这个目录执行。

## 4. 安装依赖与初始化

### 4.1 安装依赖

执行：

```bash
npm ci
```

此命令按锁文件安装项目所需程序，首次运行需要联网。安装过程中应等待命令执行结束。只有没有`npm error`、安装成功后，才继续初始化。

### 4.2 不安装Visual Studio的Windows处理方式

如果安装日志出现以下组合：

- `better-sqlite3`预编译文件下载失败，例如`ECONNRESET`；
- 随后出现`Could not find any Visual Studio installation to use`。

说明下载失败后尝试了本机编译。可以使用官方预编译包完成安装，无需安装Visual Studio。

以下文件适用于本手册核对的**better-sqlite3 12.11.1、Node.js 22（ABI 127）、Windows x64**：

[下载官方Windows驱动包](https://github.com/WiseLibs/better-sqlite3/releases/download/v12.11.1/better-sqlite3-v12.11.1-node-v127-win32-x64.tar.gz)

操作步骤：

1. 用浏览器下载，保存到当前Windows用户的“下载”文件夹，即`C:\Users\当前用户名\Downloads`。
2. 保留文件名`better-sqlite3-v12.11.1-node-v127-win32-x64.tar.gz`，不用解压。
3. 在Git Bash的项目目录执行：

```bash
npm_config_better_sqlite3_local_prebuilds="$(cygpath -w "$HOME/Downloads")" npm ci
```

此命令让驱动安装程序读取本地下载包，其他依赖仍正常安装。如果文件放在其他目录，应将`$HOME/Downloads`换成实际目录。

更新项目后，如需确认锁定的驱动版本，可执行：

```bash
node -p "require('./package-lock.json').packages['node_modules/better-sqlite3'].version"
```

若版本或电脑架构不同，应从[官方发布页面](https://github.com/WiseLibs/better-sqlite3/releases)选用对应文件。该处理方式已核对官方文件和本地提取流程，Windows动态加载仍以使用者电脑上的实际结果为准。

### 4.3 初始化网站

依赖安装成功后执行：

```bash
npm run setup
```

正常情况下会完成：

- 在不存在时根据`.env.example`创建`.env`；
- 创建数据库和附件目录；
- 生成Prisma Client；
- 应用数据库迁移；
- 初始化缺失的科目。

看到“初始化完成”后继续。初始化可重复执行，不清空已有账号、管理员设置及答疑记录，不覆盖已有`.env`。

默认保存位置：

| 文件或目录 | 用途 |
| --- | --- |
| `.env` | 本机配置及可选音视频密钥 |
| `data/dev.db` | 用户、会话、请求、消息和反馈等数据库记录 |
| `data/uploads/` | 题目图片 |
| `data/logs/` | 运行诊断日志 |

本机和普通局域网使用可先保留默认配置，`APP_ORIGIN`保持空值。初始化只创建科目，不预置学生、教师或管理员口令。

## 5. 创建管理员

### 5.1 Windows Git Bash

初始化成功后，单独执行：

```bash
winpty node.exe scripts/admin-create.mjs
```

按提示依次输入管理员账号、昵称、密码及确认密码。密码输入不显示字符，这是隐藏输入的正常表现。

账号为3—32位字母、数字、点、下划线或短横线，不区分大小写。密码为10—128个字符。自行设置并妥善保管，不使用公开共享口令。

看到“管理员已创建”即完成。该命令只创建账号，网页服务还需按第6节启动。

### 5.2 PowerShell替代方法

如Git Bash的交互终端不可用，在PowerShell执行：

```powershell
cd "$env:USERPROFILE\system"
npm.cmd run admin:create
```

其他支持交互终端的平台可在项目目录运行`npm run admin:create`。

如果提示“管理员已初始化”，应使用现有管理员登录。重复创建命令不会覆盖账号或重置密码。当前没有管理员自助找回功能；不要通过删除数据库处理密码遗忘。

## 6. 启动、访问与停止网站

### 6.1 日常使用：构建后启动

首次安装完成后执行：

```bash
npm run build
```

构建成功后执行：

```bash
npm start
```

看到服务Ready信息后，在服务电脑浏览器地址栏输入：

```text
http://localhost:3000
```

首页介绍网站功能，学生和教师分别进入各自入口。管理员在地址栏直接输入：

```text
http://localhost:3000/admin/login
```

学生、教师及管理员入口使用相应账号登录。日常使用不需要每次重新构建；代码更新后才重新执行构建。

### 6.2 开发时启动

需要修改代码并查看变化时，可执行：

```bash
npm run dev
```

开发启动会自动先执行初始化检查，然后启动服务。开发模式和构建后启动使用同一套账号与答疑业务；日常使用建议采用6.1的方式。

同一端口只运行一个服务，`npm start`和`npm run dev`不要同时占用3000端口。

### 6.3 停止与再次启动

1. 安排双方结束正在进行的答疑。
2. 在启动服务的终端按`Ctrl+C`。
3. 等待服务退出并返回命令提示符。

再次启动日常使用服务：

```bash
cd ~/system
npm start
```

终端和电脑需要保持运行。关闭服务、关机或进入睡眠后，其他设备将无法使用网站。当前没有配置操作系统开机自动启动。

## 7. 让其他电脑或手机访问

### 7.1 同一局域网访问

1. 在一台电脑上完成第2—6节，并保持服务运行。
2. 服务电脑和客户端连接到同一可互通的局域网。
3. 服务电脑在Git Bash执行：

```bash
ipconfig
```

4. 找到实际使用的Wi-Fi或以太网适配器的IPv4地址。例如`192.168.1.100`；该地址仅为示例，应使用自己电脑的实际地址。
5. 在Windows防火墙为Node.js允许可信“专用网络”访问，或由维护人员创建TCP 3000端口的专用网络入站规则。
6. 另一台电脑或手机在浏览器输入：

```text
http://192.168.1.100:3000
```

管理员入口同样使用该服务地址：

```text
http://192.168.1.100:3000/admin/login
```

客户端只需浏览器，无需再安装项目。学生和教师都通过同一服务地址登录，数据统一存储在服务电脑。

`localhost`始终表示正在使用浏览器的那台设备；客户端访问服务电脑时应使用服务电脑的IP。`0.0.0.0`是服务监听地址，不作为浏览器访问地址。

服务电脑的IP可能随网络变化。实地长期使用时，可由网络维护人员配置固定局域网地址或DHCP地址保留。部分访客Wi-Fi和校园网隔离设备，即使连接同一Wi-Fi也可能无法互访。

### 7.2 不同地点通过互联网访问

当前本机地址不等于公网网站地址。公网运行需要维护人员另外完成：

- 在有持久化磁盘的单实例服务器安装项目；
- 按本手册安装、初始化、创建管理员并构建；
- 配置正式访问地址、HTTPS反向代理和网络规则；
- 将`.env`中的`APP_ORIGIN`设为准确外部源，例如`https://qa.example.com`，再重启服务；
- 配置操作系统层面的服务启动及备份，并完成实际跨设备验收。

HTTPS反向代理场景可让应用只监听本机：`npm start -- --hostname 127.0.0.1`。代理配置由维护人员依据实际服务器处理。`APP_ORIGIN`是协议、域名及可选端口，不带页面路径或尾部斜杠。

当前SQLite和附件方案要求单实例持久化磁盘；不直接使用无持久化存储的Serverless，也不让多个应用实例共享该文件数据库。本项目未自动购买服务或部署公网。

## 8. 学生、教师与管理员操作

### 8.1 教师注册及资料审核

1. 打开网站首页，选择教师入口并进入注册页`/teacher/register`。
2. 填写账号、昵称、密码和确认密码。
3. 填写当前就读学校、在读层次、至少20字的擅长方向，选择可答科目。
4. 确认已成年、全日制在校、非在职，并阅读同意条款。
5. 提交注册，进入教师工作台。

新教师默认离线且待审核，暂时不能上线接单。管理员应核对填写的资格与可答范围，决定是否启用。资料由本人声明，不上传身份证或学籍证明。

教师修改学校、在读层次、介绍或可答科目等审核相关资料后，可能需要重新审核，以页面显示的状态为准。

### 8.2 管理员启用教师

1. 访问`/admin/login`，登录管理员账号。
2. 在管理页面找到教师列表。
3. 核对对应教师的账号、学校、在读层次、介绍及科目。
4. 勾选启用项，设置允许接单的科目。
5. 点击“保存设置”，确认显示保存成功。

修改后教师可刷新工作台确认权限。未启用的教师不会被匹配。管理员可以停用接单权限，但停用不等于删除账号及历史。

### 8.3 教师上线与接单

1. 从`/teacher/login`登录，进入教师工作台。
2. 确认接单权限已启用、科目正确。
3. 点击“开始接单”，检查状态显示为可接单。
4. 保持页面、网络和电脑运行。
5. 新邀请出现在待处理请求中，查看问题与接单剩余时间。
6. 点击“接受请求”进入答疑室；不便答疑时可点击“拒绝请求”。

默认每次邀请最多等待20秒，总匹配等待上限60秒，实际以服务器配置为准。教师已有邀请或答疑时不能再被安排第二个请求。

停止接收新邀请时点击“暂停接单”。页面关闭或心跳过期后，不再被视为可接单；默认心跳有效期30秒，离线显示可能存在短暂延迟。

### 8.4 学生注册及提问

1. 从首页进入学生注册页`/student/register`。
2. 填写账号、昵称、密码与确认密码，确认成年在校及条款。
3. 注册或从`/student/login`登录，进入学生主页。
4. 点击“发起提问”，选择科目。
5. 填写20—2000字的具体问题，说明题目、已尝试的思路和卡住的位置。
6. 如需图片，上传最多1张PNG、JPEG或WebP，大小不超过5MB。
7. 选择“指定教师”或“快速匹配”，点击“发出答疑请求”。

指定教师只邀请所选教师，拒绝后由学生重新选择。快速匹配寻找科目相符、已启用、在线且空闲的教师。没有在线教师时会正常等待，不自动生成答疑结果。

等待期间可取消。每位学生同时最多有一个未结束请求。提交失败时查看提示；网络失败后的原页面重试使用同一请求标识，避免重复创建。

### 8.5 答疑室交流、结束与反馈

1. 教师接受后，双方进入各自门户中对应的同一个答疑室。
2. 双方都进入后开始计算答疑时长。
3. 查看原问题和题目图片，输入文字并发送，消息通常约2秒同步。
4. 发送失败时使用页面的重试操作；刷新可恢复已存储的消息及原开始时间。
5. 任一方点击“结束答疑”，另一端同步结束，输入框禁用。
6. 学生进入反馈页，选择已解决／部分解决／未解决、1—5分满意度，并可填写最多500字意见。
7. 提交后确认反馈已保存，每场会话最多一条反馈。

答疑没有固定课时，结束后可再次提问。短暂断网可重连；长期无人返回的会话会按配置失联回收，默认30分钟，失联回收的会话不开放反馈。

### 8.6 历史、资料和统计

- 学生和教师从各自的“答疑记录”查看本人相关问题、对方昵称、状态、时间及有权限的消息和反馈。
- 从“个人资料”修改本人资料或口令；修改口令需要当前口令，之后本账号其他登录会话失效。
- 同一浏览器中的学生与教师Cookie独立，退出一端不会退出另一端；同一门户的多个普通标签仍共享该门户登录身份。
- 管理员查看真实请求、匹配、完成、取消、超时、反馈及科目统计。
- 管理员导出的CSV为汇总数据，不包含私人聊天、题目图片或口令摘要。

## 9. 首次使用核对表

首次现场使用前，由维护人员、学生和教师一起完成：

- [ ] 网站首页和三端登录入口能够访问。
- [ ] 管理员已初始化，学生和教师已分别注册。
- [ ] 管理员启用教师并保存正确科目。
- [ ] 教师主动上线，学生看到其可接单状态。
- [ ] 学生发出请求，教师实际收到并接受。
- [ ] 双方进入同一答疑室，分别发送不同文字，并在对方页面读取。
- [ ] 刷新页面后，消息和开始时间恢复。
- [ ] 任一方结束，双方输入框都禁用。
- [ ] 学生提交反馈，历史和管理员统计正确更新。
- [ ] 实际客户端访问的是同一服务地址，服务电脑未进入睡眠。

建议使用两台设备；也可用两个浏览器或普通窗口加无痕窗口。验证两位同角色用户时必须隔离浏览器会话。

## 10. 音视频功能说明

### 10.1 默认设备预览

默认配置`RTC_PROVIDER=demo`表示本地设备预览。界面会显示“设备预览模式，尚未接入双人音视频”。

用户主动点击后，可以检查自己的摄像头和麦克风。默认不会接入对方视频，也不会录音录像。拒绝设备权限时仍可进行文字答疑。

摄像头和麦克风通常需要localhost或HTTPS安全浏览器上下文。通过普通HTTP局域网IP访问时，文字答疑可用，设备权限可能被浏览器限制。

### 10.2 接入真实双人通话

维护人员已有LiveKit服务与凭据时，在服务电脑的`.env`配置：

```dotenv
RTC_PROVIDER=livekit
LIVEKIT_URL=wss://your-project.example
LIVEKIT_API_KEY=your-server-key
LIVEKIT_API_SECRET=your-server-secret
```

以上为占位示例，应填写实际值并重启服务。密钥只保存在服务端，不能使用`NEXT_PUBLIC`前缀，也不提交GitHub。

两台独立设备完成匹配后分别连接，实际检查能否看到和听到对方、静音、关闭摄像头、网络重连及结束后双方退出。没有真实凭据和手工验收时，不能将设备预览或SDK模拟描述为双人通话已验证。当前交付尚未完成真实LiveKit端到端验收。

## 11. 日常维护与版本更新

### 11.1 每次启动

已安装、初始化和构建完成的电脑，日常只需：

```bash
cd ~/system
npm start
```

确认Ready后再通知用户登录。无需每天下载代码、重新创建管理员或重复注册用户。

### 11.2 更新网站

1. 安排用户结束答疑，停止服务。
2. 按第12节备份现有数据和配置。
3. 在项目目录执行，并确认每一步成功：

```bash
git pull --ff-only
npm ci
npm run setup
npm run build
```

4. 如安装再次遇到驱动下载问题，按4.2处理对应版本。
5. 全部成功后执行`npm start`，核对登录、目录及历史记录。

`git pull`提示本地修改冲突时，应先保留并核对修改，再由维护人员处理；不要用强制重置覆盖未确认的工作。安装或迁移失败时先处理失败，不跳过失败直接启动。

### 11.3 运行监控

管理员页面显示运行版本、时长、内存和最近异常／退出摘要。父监督进程默认10分钟内最多重启3次；主动停止不会自动重启。

日志默认位于`data/logs/application.jsonl`，按容量轮转。JavaScript try/catch不能拦截原生崩溃、系统终止或掉电，监督进程只能报告其观察到的退出码和信号。反复退出时，应结合终端与安全日志排查原因。

## 12. 数据备份、恢复与迁移

### 12.1 备份

1. 安排用户结束答疑，停止服务并确认进程退出。
2. 将完整`data/`目录复制到单独的备份位置，保留数据库、可能存在的SQLite伴随文件和附件。
3. 单独保存`.env`，如使用自定义数据库／附件目录，还需备份这些实际目录。
4. 给备份标注日期、代码版本和来源电脑，妥善保存。

不要只复制正在写入的`dev.db`文件。完整备份应在服务停止后进行，数据库与图片需要保持对应关系。账号口令摘要、聊天、图片和配置属于非公开数据，备份不上传GitHub。

### 12.2 在另一台电脑沿用原有数据

1. 在源电脑按12.1停止并备份。
2. 在目标电脑安装Git、Node.js并克隆项目。
3. 安装依赖；如需还原较早备份，由维护人员选择对应或兼容的代码版本。
4. 保持目标服务停止，把目标已有数据另行备份，再将源电脑的完整`data/`和`.env`复制到目标项目目录。
5. 检查`.env`中的路径。默认相对路径可随项目迁移；绝对路径应调整到目标电脑的实际位置。访问地址改变时核对`APP_ORIGIN`。
6. 执行`npm run setup`应用所需迁移，再执行`npm run build`和`npm start`。
7. 使用原有账号重新登录，核对历史、图片和统计。

完整数据库迁移后已有管理员账号仍保留，不需再次创建。仅克隆GitHub代码不能迁移原有账号或聊天。切换平台服务时，应停止源服务，以目标电脑作为统一访问入口；分别修改两份数据库后不会自动合并。

### 12.3 恢复备份

停止目标服务，先备份当前状态，再由维护人员恢复成套数据库、附件和配置，并使用兼容代码启动。若恢复更早的数据库备份，备份之后新增的数据不会包含在其中。不要运行`prisma migrate reset`处理日常故障。

## 13. 常见问题处理

| 现象 | 原因或处理步骤 |
| --- | --- |
| `node`、`npm`或`git`找不到 | 检查安装和PATH；安装后重新打开终端 |
| Node版本为24或其他不支持版本 | 使用22 LTS，再执行`npm ci`重装原生依赖 |
| `better-sqlite3`出现`ECONNRESET`及Visual Studio提示 | 按4.2下载并使用官方本地预编译包 |
| `dotenv`、`tsx`找不到 | 通常是`npm ci`未完成；先解决安装错误，再重新安装依赖 |
| 找不到`../generated/prisma/client` | 依赖安装成功后执行`npm run setup`生成客户端 |
| `spawnSync npx.cmd EINVAL` | 更新旧版代码；当前初始化使用Node直接运行本地CLI |
| 管理员创建提示需要交互终端 | Git Bash使用`winpty node.exe scripts/admin-create.mjs`；PowerShell使用`npm.cmd run admin:create` |
| `winpty: cannot start 'npm'` | 改为上一行的`node.exe`直接入口 |
| 提示管理员已初始化 | 使用原有账号；创建命令不重置口令 |
| PowerShell提示脚本执行受限 | npm命令使用`npm.cmd`，例如`npm.cmd start` |
| `EADDRINUSE`，3000端口被占用 | 核对已有服务，停止自己启动的旧服务；不要再重复启动 |
| 浏览器打不开localhost | 检查服务是否Ready、是否已退出，以及实际监听端口 |
| 其他设备打不开 | 检查服务IP、同网互通、防火墙规则、电脑睡眠和Wi-Fi设备隔离 |
| 页面打开但提交显示来源校验失败 | 检查`.env`的`APP_ORIGIN`是否与实际外部协议、地址及端口一致；本机／普通局域网可保留空值 |
| 教师不能点击开始接单 | 检查管理员是否启用、科目是否正确、资料是否需要重新审核 |
| 学生看不到在线教师 | 检查双方是否访问同一服务、教师是否主动上线及心跳有效、科目是否匹配 |
| 等待超时或指定教师拒绝 | 由学生重新选择或重新请求，不会创建虚假会话 |
| 修改代码后生产页面没变化 | 停止服务，重新执行`npm run build`，再`npm start` |
| 原生`RemoveEnvironmentCleanupHook`／`Statement`崩溃 | 检查实际Node版本是否22.x，换版本后用`npm ci`重装；结合退出日志排查 |
| 摄像头或麦克风无法开启 | 检查设备权限、设备是否存在及安全上下文；文字功能仍可使用 |
| 音视频配置后失败 | 检查LiveKit凭据与网络、服务是否重启及HTTPS；依据真实连接状态处理 |

若需要临时使用其他端口，在停止原服务后可执行`npm start -- --port 3001`，浏览器地址及客户端访问地址同时改用3001端口。

报告故障时提供操作步骤、时间、报错文字及错误编号；不提供密码、Cookie、RTC令牌或完整密钥配置。
